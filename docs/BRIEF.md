# 产品简报：时迹（Timetrace，暂定名）

一个**纯本地**的桌面客户端（Tauri / Electron 未定）。它读取各种 LLM 编码工具的会话日志，告诉用户：**一个需求的时间花在了哪**。

## 1. 核心价值
看清时间花在哪。按「需求」聚合，把时间拆成阶段，再给出洞察和建议。

## 2. 用户
先自用（后端开发，Go / Python），后续开源。重度使用多个 AI 编码工具，经常同时开多个会话。

## 3. 核心概念
- **会话（session）**：某个工具的一份日志文件。
- **轮（turn）**：从用户发一条消息，到 AI / 工具的最后一个事件。
- **需求（requirement）**：自动聚合而来（同一 cwd，相邻会话间隔 ≤ 4 小时），可手动合并 / 拆分 / 改名，人工修正会被保留。
- **阶段**（纯规则判定，可人工改）：聊方案 P、调研 R、写代码 C、改代码 F、测试 T、其他 O。
- **等我 W**：AI 做完了，在等用户（轮之后、低于空闲阈值的间隔）。
- **空闲**：间隔 ≥ 阈值（默认 10 分钟，可调），用户不在，**不计入**。
- **活跃时间** = AI 时间 + 等我。
- **并发**：同一需求下的多个会话允许重叠，各算各的。

## 4. 精度分档（界面必须体现）
- **精确档**：每个事件都有时间戳 → 显示轮级、阶段级耗时。
- **粗略档**：只有会话起止时间（如 Cursor 转录）→ 耗时显示「–」并带「粗略」徽标，只显示次数和跨度；**不估算，不计入汇总数字**，并加一条说明。
- 适配器缺失的可选字段（token、模型、费用等）一律显示灰色「–」，不推测。

## 5. 支持的工具（首批）
Claude Code、Codex CLI、pi、omp、Cursor（仅转录，粗略档）。以后新增工具 = 新增适配器，界面不改。

## 6. 页面清单
1. **需求列表**：每行一个需求，显示总活跃时间、阶段构成条、涉及的工具、最近活动。
2. **需求明细**：阶段分布、会话列表、时间轴。
3. **时间轴**：按轮展示，阶段色块；点击一轮打开右侧**对话抽屉**。
4. **对话抽屉**：该轮的消息与工具调用（span：LLM / 工具 / 权限等待 / 子 agent）。
5. **今日面板**：今天各需求花了多久，正在运行的轮到「现在」为止。
6. **洞察页（Dashboard）**：最耗时的阶段、较上期变化（仅当上期有数据）、Top 需求、最多 4 条建议（默认本地规则生成；用户自己配置大模型后可手动触发，发送前预览发送内容）。
7. **设置**：数据源与能力矩阵、空闲阈值、聚合窗口、阶段规则、可选大模型（默认关闭）。
8. **空态与异常**：未发现日志、某文件解析失败（有原因且不影响其他文件）、粗略档说明。
9. （P1）**过程视图**：单个会话的 span 树。

## 7. 视觉编码规则（已定，不要改）
阶段 = **颜色 + 填充纹理 + 字母 + 图标** 四重编码，不能只靠颜色。
- 字母：P R C F T O，等我 W。
- 图标（24px 网格，描边 1.75，圆头，currentColor）：聊方案=气泡、调研=放大镜、写代码=`</>`、改代码=带加减的方块、测试=烧瓶、其他=圆里三点、等我=沙漏、空闲=月亮。
- span 类型：LLM=火花、工具=扳手、权限=锁、子 agent=分支。
- 宽度 <6px 时去掉纹理；宽度 ≥16px 时显示图标。
- 亮色 / 暗色两套主题都要有。

## 8. 硬性约束
- 数据全程本地，**没有账号、云同步、遥测入口**。
- 大模型建议默认关闭；打开后只能手动触发；发送范围三档（仅聚合数 [默认] / 加需求名 / 加分段摘要），发送前预览 JSON；支持本地模型（Ollama）。
- 所有数字由本地计算；大模型只做解读，不得编造数字。
- 不写「高于正常水平」之类的断言（没有可信基线）；相关性建议要标明「相关，不等于因果」。

## 9. 已有原型（见 design/ 与 out/）
两个视觉方向：**A 仪器台**（偏密、偏工具感）与 **B 留白**（偏松、偏阅读）。尚未选定。请在其中一个的基础上改进，或明确指出哪里应该融合。
